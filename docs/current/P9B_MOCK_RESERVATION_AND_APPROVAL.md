# P9B — Controlled ASP Mock reservation and independent Practice approval

Date: 2026-11-04. Status: **source implemented, disposable PostgreSQL security tests required; NOT installed on live Supabase.**

## Business contract and non-goals
ASP source bank may contain the historical 1,625 Demo items, but production questions must be imported separately as DRAFT and individually reviewed for source rights, checked answers, official ASP11 domain, and Low/Medium/High difficulty. No 5-old-worksheet → 9-domain auto-mapping, auto-approval or auto-classification.

The official Mock requires **exactly 200 stable, distinct question IDs**, reserved in a versioned, audit-traced PRIVATE form. These IDs must be non-public, NEVER eligible for Quick 10 / Timed / Custom / Domain / Level Up / weakest / missed / trial / learning quiz. Reserving the form does **not** deliver a timed Mock; Mock engine 200 questions / 300 minutes remains future and must be separately tested.

Only after reserving Mock can a separately authorized **second Admin**, who was NOT the original P6A reviewer, approve ONE reviewed non-Mock DRAFT question into the real P4 Practice pool. P8e 70%-of-ORIGINAL-stage correct target is unaffected. A reviewed READY question is NOT automatically approved.

`supabase/migrations/202611040005_p9b_controlled_mock_reservation_and_practice_approval.sql`
- Prerequisites: installed P1/P2/P4/P5/P6A/P8e in the confirmed dedicated Technica STAGING project; independent verified Admin accounts. P9A read-only preflight is optional. **Do not execute in Production by default**; the user recently showed `main — PRODUCTION` in Supabase.
- Guarded schema adds private RLS-on `lms_p9b_mock_forms` and `lms_p9b_mock_items` (no anon/auth table grants), fixed version 1 and exactly 200 positions. Installation is schema-only, ZERO existing question/learner data DML. Form/ordered ID rows cannot be edited/deleted by ordinary update; a trigger prevents reserved question unflagging, modifying answer keys/text/source/difficulty or approving it for Practice.
- Protected admin-only `lms_p9b_mock_preflight(course,ids)` returns aggregate counts/readiness ONLY, no answers, question text or rights notes. Requires exactly 200 individually selected, distinct, DRAFT, unused, not already reserved, personally checked (answer AND commercial rights), ready-review, classified into official ASP11 questions. Current Mock flags must be zero; existing legacy reserved flags without an immutable form are a BLOCKER requiring separate review, not silent deletion. Nine official ASP11 domains must exist.
- Protected `lms_p9b_reserve_mock(course,ids,exact_phrase)` locks ASP course and each selected question/review, revalidates **inside transaction**, inserts 200 ordered form references and sets ONLY those 200 `mock_exclusive=true` (questions remain DRAFT) and redacted audit entry. Any invalid item/role/count/duplicate/concurrency failure rolls back the entire operation. Exact phrase: `RESERVE 200 ASP MOCK QUESTIONS`. Replays fail closed; this first version intentionally allows only one immutable form per ASP course. A future replacement needs a separate migration/review.
- Protected `lms_p9b_approve_practice_question(question_id,exact_phrase)` requires active verified Admin different from `lms_p6_question_reviews.reviewed_by`; exactly 200 form IDs still reserved; personally checked rights and answer, READY state, official domain/difficulty, non-Mock DRAFT unused question. Copies ONLY approved domain and difficulty to P4 question and updates `approval_state` to `approved`. One question per call and an audit entry; no batch approval. Exact phrase `APPROVE ASP PRACTICE QUESTION` is sent by the UI only after explicit click/confirmation.
- Both operations are deterministic fail-closed, still rely on server Auth/JWT rather than browser role hints, and do not change P8e answer keys, attempt snapshots, learner permissions, P4 RLS or other modes.

## Admin interface (English, existing ASP Review card)
- Filter `Reviewed · ready`, browse 20 per page, tick *exactly 200* reviewed DRAFT question IDs; selection is kept in React state across pages (not localStorage).
- `Exclusive Mock reservation` checks selected count, queries Admin-only read-only server preflight, displays eligibility and existing reserved blockers; requires an exact typed confirmation and secondary confirmation before atomic reservation. Selection is never random or automatic.
- After the exact-200 reservation is complete, choose a different reviewed non-Mock item. A second independent Admin can click `Approve ONE for Practice` after a confirmation; server rejects reviewer self-approval or pre-reservation attempts. No button can override bank shortage/rights or release multiple rows.
- When P9B SQL is not installed, the functions return a displayed error; there is NO client-side fallback or simulated success. A reviewer cannot see an unauthorized private Mock selection or learner answers from these P9B RPCs.
- P9A's historical read-only release flag remains deliberately **false**, because even with 200 reserved items, Mock exam delivery, version lifecycle, and full paid-release acceptance remain absent.
