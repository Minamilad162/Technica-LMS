# P14 — Secure PDF & Video Lessons (Admin Tools → Courses)

**Environment status: GitHub SOURCE + disposable CI only.** P14 has NOT been installed on the user's actual Supabase Staging/Production project, no real file has been uploaded, and no live deployment was authorized. Owner requested uploadable video/PDF per Lesson and strong anti-download/capture protections, preserving the course hierarchy and existing legacy reading content.

## User workflow

**Admin Tools → Courses → Course → Domain → Topic → Lesson** now offers **+ PDF**, **+ Video**, optional **+ Text** (legacy lessons preserved), **Preview** and Rename. PDF accepts `.pdf` (max 20 MiB); Video accepts `.mp4` / `.webm` (max 50 MiB). Both use private signed uploads with server-verified Admin Auth. The Lesson remains Draft/published under existing P1 Admin controls; uploading does **not** auto-publish or mark completion. All content is displayed through the shared **SecureLessonContent** component inside actual `SupabaseApp.jsx` and the React learner `LiveLearning.jsx`.

PDF/video are *not* plaintext browser bundle assets, do not get a public bucket URL, and only the Edge function can sign viewing links. The existing P1/P2 course/lesson entitlement and Trial lesson grant gate remains authoritative. Existing reading-text blocks are still displayed, while PDF/video use real `lms_lesson_blocks` referencing a private server-side `lms_media_assets` object.

## Private storage and authorization design

1. **One Staging-first SQL migration:** `supabase/migrations/202611060001_p14_private_lesson_media.sql` creates **private** bucket `technica-private-lessons` (50 MiB bucket limit; PDF 20 MiB app limit) with strict MIME allowlist, and service-only `lms_p14_media_upload_intents` table. Atomic service-only `lms_p14_finalize_media(uuid)` locks the one-time intent, rechecks Storage `objects.metadata` real size/MIME, creates private media metadata + lesson block and marks intent finalized in one transaction. It rejects duplicate use, stale intent and mismatched file. Does not alter existing user/question/lesson data.
2. **Supabase Edge Function `supabase/functions/technica-lesson-media/index.ts`:** `verify_jwt = true`, allows ONLY specifically configured site origin(s), checks a real signed-in Auth JWT and active LMS profile. For **init-upload**, checks live Admin role, file name/type/size, and actual Lesson→Topic→Domain→Course ownership, then creates one-time upload intent and short-lived signed *upload* token for a unique storage key. Client uploads directly to private Storage, never exposing a service key in the browser. For **finish-upload**, verifies same Admin owns active intent and invokes service-only finalizer. For **view**, rechecks `lms_p1_can_view_lesson` and selected lesson-block's existing RLS, then validates private asset/course/kind before issuing a 120-second private read URL.
3. **Browser media API `src/production/lessonMediaApi.js`:** validates PDF/MP4/WebM extension/MIME/max size/header before sending, uses `functions.invoke` and `uploadToSignedUrl`, never `getPublicUrl`, never direct `lms_media_assets` select, and removes `assetId`/storage paths from returned learner-facing blocks. Local header checks are a UX warning, **not** virus scanning. The Edge/database are security authorities.
4. **Viewer `SecureLessonMedia.jsx`:** video has native controls with `controlsList="nodownload noplaybackrate noremoteplayback"` and disabled Picture-in-Picture; document is embedded with toolbars hidden where supported, not offered as a file download control. Both show a changing account-linked watermark. Right-click, copy, drag, print and save shortcuts are discouraged/blocked when capture originates in the page. When browser tab becomes hidden, content is concealed, and the URL is requested again upon return. Signed URLs are refreshed to allow longer video sessions and expire after 120s. A restricted/expired/revoked account cannot obtain **new** playback tokens; an already issued URL remains valid until expiry.
5. **Do not treat the display-only controls as DRM.** Native browser PDF renderers may still expose print/save via built-in browser menus and developer/network tools, and HTTP video bytes can still be copied from network traffic. Browser JavaScript **cannot reliably stop OS screenshots, external screen recorders or another camera**. Watermarks provide attribution/deterrence; they do not stop captured pixels. For strong high-value video, a **commercial multi-DRM platform (Widevine + FairPlay) using protected license and encrypted streaming** is necessary. For stricter PDF protection, server-rasterized per-page tiles, on-screen user watermark and limited-time access are an additional future delivery method; no universal screenshot-proof PDF exists in browsers. Never claim 100% prevention, particularly Android/iOS.
6. **Performance and limits:** Supabase plan storage / CDN upload limits, 50 MiB max video (not a platform for long 1GB courses), browser PDF toolbar differences, video token refresh/seeking and mobile Safari behavior all require real device/Staging testing. For longer videos, use dedicated encrypted streaming provider, not raw MP4 in private Storage. Signed upload token validity is controlled by Supabase Storage (currently 2 hours), server upload intent also expires after 2h.

## Safe deployment (once a dedicated Staging project is authorized)

1. Ensure P1 LMS foundation exists and check **actual target is Staging, not main/PRODUCTION**; take schema backup.
2. Run **only this new SQL file** once in authorized Staging SQL Editor. Confirm bucket is **private**, allowed MIME list and size limit, and service-only functions/grants. Do **not** create public policies for `storage.objects` on this bucket, even if an unrelated course bucket has permissive rules.
3. In Staging Edge Functions secrets set `TECHNICA_MEDIA_ALLOWED_ORIGINS` to an exact comma-delimited allowlist of the trusted *site origins* (for example `https://your-staging.example.com`); no trailing slash. Supabase runtime provides `SUPABASE_URL` and an Admin-capable secret key **server-side only**. **Never put service/secret keys into VITE_ variables or GitHub.**
4. Deploy `technica-lesson-media` function with normal JWT verification **enabled** using Supabase CLI / approved deployment flow, never `--no-verify-jwt`.
5. Build/deploy the React app to *Staging* after migration/function; sign in as actual LMS Admin. Attach one small private PDF and one short MP4 to a published/granted fixture Lesson. Verify signed playback in Admin and authorized Paid/Trial; ensure Trial cannot view other Lessons, suspended/unentitled users get 403, and `storage.objects` cannot be directly listed/downloaded. Test expired links, failed uploads, duplicate finalize, print/copy deterrence and iOS/Android native captures. Keep logs clean of tokens, URLs, filenames and private learner IDs.
6. For **Production**, require separate explicit owner approval, production backup, staging evidence, domain/CORS configuration and migration/deployment plan. There is no automatic production release.
