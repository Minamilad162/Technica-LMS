# P20 — Direct Course Media & Cross-page Loading Performance

Status: implementation in GitHub source; no Supabase SQL/Edge function changes or real production-data writes.

## User-observed issues
- Course Video/PDF opens a large dark **Open Protected Video/PDF** poster first; learner must press that button and request native Fullscreen. User requires **immediate inline lesson access**, with Fullscreen as an *optional* control.
- A real desktop/mobile screenshot still records media. That is an expected platform limitation of ordinary web browsers, **not a bug solved by a DOM blackout**. Browser APIs cannot detect or force-black every OS screenshot/recording.
- App route navigation and content loading feel slow. Source review identified: many heavy Admin/Mock/Practice/Review page imports bundled eagerly in `src/App.jsx`; a second synchronous import chain into the almost 1-MB *demo-only* ASP question bank through `src/lib/store.jsx`/mock.js; sequential identity/profile/role/catalog requests and unnecessary initial private-media authorization for content far below the viewport. Performance measurements from an actual user's device and network have not been collected; no invented before/after LCP or timing metrics.

## Implemented changes
1. `src/production/ProtectedLessonViewer.jsx`: authorized PDF and video **appear inline automatically** when near the viewport. No intermediate Open Protected button or native fullscreen gate. Video retains its ordinary Play control (autoplay with audio is browser restricted); PDFs load immediately into the iframe. A visible **Fullscreen (optional)** button requests native Element fullscreen, with a compatible inline fallback. RLS, JWT and existing P14 signed URL still authorize *every* protected read before `src` is assigned; no browser demo flags or entitlement bypass.
2. Only media elements within ~450 px of viewport request a signed URL via IntersectionObserver. This prevents loading offscreen media objects at once; visible or near-visible media loads without click. If IntersectionObserver isn't supported, loads immediately. Signed URL is requested again after conceal/recovery. Removed the 95-second unconditional timer that restarted playing video and reset PDF scrolling. Video/PDF error shows Retry rather than silent repeat loops.
3. Keep the existing best-effort protection: watermark; no-download/PiP/remote-playback video control hints; copy/context-menu/drag deterrence; hide and pause/unmount media synchronously on page hiding, browser window blur where reliable, known screenshot/print keyboard shortcuts, and beforeprint. **Same black PROTECTED LEARNING CONTENT** screen on recognized events; automatically resumes and reauthenticates when focus returns, with an optional Resume control. Print protection class remains installed while a viewer is mounted, including while blacked out.
4. `src/App.jsx`: **21** heavy React Router screens are imported using `React.lazy` with Suspense fallback, instead of eagerly shipping those modules to all visitors. Existing route URLs, AdminOnly gates, local Demo preview, assessment and quiz functionality remain structurally unchanged. `LiveLearnerWorkspace.jsx` independently code-splits Practice engine, PDF/video lesson content, Checkout and Premium My Learning, including for the separate Supabase-Vite entrypoint.
5. `src/production/lmsApi.js` loads profile and role assignments in parallel. `src/production/learnerJourneyApi.js` loads identity, published Course metadata and active P1 entitlements in parallel; it asks the DB for **only published Courses**, not all draft+published rows. Keeps active-profile verification **before returning any data to UI**, with existing RLS enforced on every query.
6. Changes are source-only; P14/P15/P17 migrations and private/public buckets are unchanged. No code that creates or grants entitlements, payments or exam scores is modified.

## Security limitations
- A Windows/macOS screenshot, browser extension, Android/iOS hardware-button screenshot, OS screen recording, screen sharing or external camera can still capture screen pixels. On some desktops, browser focus loss may trigger the black overlay before capture, but the capture tool may snap before the browser receives or paints that event. Never claim screenshots were disabled. For stronger defense, evaluate provider-managed DRM/native secure windows and legal/operational control of content distribution.
- Standard PDF browser iframe still may expose native browser download/print UI; `#toolbar=0` is just a hint. P14.1 canvas/rasterized pages are a *separate* future authorized implementation. This change retains the already private signed URL control.
- A player with audio **will not auto-play sound** until the user presses Play in most browsers; direct display means playback controls visible, not forced autoplay.
- Fullscreen-exit is no longer a privacy violation: it is optional now, and the user may go back to normal inline view.
